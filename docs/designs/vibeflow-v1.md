# Design: Outflow v1 — read selected text aloud, naturally

> Renamed from Outflow to VibeFlow on 2026-10-01. The text below keeps the original name as a historical record.

Generated by /office-hours on 2026-10-01
Branch: main
Repo: outflow (local, no remote yet)

Mode: Builder

## Problem Statement

Florian dictates with Wispr Flow every day but has no equally natural way to have the Mac read text back. macOS Speak Selection exists but sounds robotic, has no per-app presets and no pre-processing. Outflow is the counterpart to Flow: select text anywhere, press a global shortcut, hear it in a natural voice within 1.5 seconds, press again to stop.

## What Makes This Cool

- Voice quality first. ElevenLabs Flash v2.5 streamed over HTTP, Apple voices as the free offline fallback that is used automatically when there is no key or no network (rule in Provider selection below). "as pleasant of a voice as possible" is the one criterion that kept coming back.
- Smart read. A second shortcut sends the selection through Claude for a brief or a cleanup before speaking. A sprawling coding-agent response or a 5k-character contract becomes a 20-second spoken brief. None of the five neighbours inspected (listed under Landscape) has an LLM step.
- Per-app presets keyed by bundle id: calm narrator for PDFs and Mail, fast voice for Slack, Apple-only with smart read disabled for apps holding sensitive text.
- v2 direction (Codex): a "depth dial" where one listening session holds the summary, the source passage behind each point and the original, so you can go deeper without rereading. Plus a floating karaoke overlay driven by the ElevenLabs alignment data v1 already receives.

## Constraints

- Solo, open source, learning Swift while building. Xcode is not installed yet (Command Line Tools with Swift 6.3.2 only).
- Bring your own keys for ElevenLabs and Anthropic, stored in the macOS Keychain. No accounts, no billing, no server, no database.
- No signed DMG in v1. Local Xcode build with a stable signing identity so the Accessibility grant survives rebuilds.
- Exactly one runtime permission in v1: Accessibility. No user notifications, so no UNUserNotificationCenter prompt; every status and error is shown in the menu bar.
- Capture must work in Safari, Mail, Notes, VS Code and other Electron apps, Preview PDFs and Terminal.
- Data handling: a plain read sends the selected text to ElevenLabs; a smart read also sends it to Anthropic. The README and the first-run screen state this in one line, and a per-app preset can keep an app fully local (Apple voice, smart read disabled).

## Landscape

Open source macOS read-aloud menu bar apps inspected on 2026-10-01, all solo projects at 1 to 2 stars:
- Tristr-Flow, https://github.com/zvone187/Tristr-Flow (Electron, ElevenLabs, floating karaoke overlay, captures via Edit > Copy through Accessibility with clipboard restore)
- Just Aloud, https://github.com/Kian-hdr/just-aloud (Swift, ElevenLabs + local Kokoro, rewind/pause/forward, Keychain, Unlicense, ships a notarized DMG)
- Aloud, https://github.com/fabianaitech/Aloud (Swift + Python daemon, Apple voices or Kokoro-82M, Services menu, MIT)
- aloud, https://github.com/tilakp/aloud (on-device Kokoro, no cloud)
- whisper-shortcut, https://github.com/mgsgde/whisper-shortcut (dictate + read aloud + AI chat, bring your own keys)
None has an LLM pre-read step or per-app presets. Only Just Aloud ships an installable.

## Premises

1. v1 = core reader + smart read. Follow-along highlight deferred to v2 as a floating overlay, never drawn inside the source app (macOS has no app-agnostic way to paint on another app's text; every neighbour converged on an overlay).
2. Selection capture: AXSelectedText first, then press the frontmost app's Edit > Copy menu item via Accessibility with a pasteboard snapshot and restore (accounting in Capture below).
3. Playback: one ElevenLabs streaming request per selection feeding one audio player. Chunk only above the model input limit, using previous_text and next_text for continuity. Sentence-level concurrent synthesis rejected after the Codex challenge.
4. Differentiators are smart read and per-app presets. The plain reader is table stakes and matches Just Aloud feature for feature.
5. Keys live in Keychain, never in a file or UserDefaults.
6. Swift 6 / SwiftUI with MenuBarExtra. Xcode project generated by XcodeGen from project.yml. No Electron, no Tauri.
7. Distribution deferred: v1 is a local build; a notarized DMG via GitHub Actions is v2.

Ruled out during the session: signed/notarized DMG in v1 (not needed yet); in-app highlight (field proved unreliable); Electron (would add a runtime without helping with hotkeys, Accessibility or audio); AXSwift as a dependency (predates Swift 6 strict concurrency, and the three calls needed are wrapped directly); user notifications (second permission prompt for little gain); smart-read input truncation (the size guard is the only limit).

## Approaches Considered

### Approach A: Single app target
Everything in one Xcode target. Fewest files, fastest first sound. Rejected: the logic that most needs tests (session cancellation, pasteboard timing) would only be testable by launching an app that needs Accessibility permission.

### Approach B: Thin app + local OutflowCore package (chosen)
App target holds SwiftUI, menu bar and permissions. A local Swift package holds capture, providers, session state machine, smart read and settings as plain Swift behind injectable protocols, with a Swift Testing target. Same dependencies as A plus one Package.swift.

### Approach C: Fork Just Aloud
Rebrand an existing Swift reader and add smart read and presets. Rejected: inherits an unknown 2-star codebase, a Python Kokoro dependency and their settings model; learning Swift through someone else's choices.

### Protocol seams (what makes OutflowCore testable)

| Protocol | Real implementation (app target, Live/) | Test fake |
|---|---|---|
| Pasteboard | NSPasteboard.general | in-memory items + changeCount |
| AccessibilityBridge | AXUIElement calls, AXIsProcessTrusted | scripted selection or failure |
| SpeechProvider | ElevenLabsProvider, AppleSpeechProvider | emits scripted audio chunks or speaks silently, can be slow or fail |
| AudioPlayer | PCMStreamPlayer on AVAudioEngine | records scheduled buffers, rate and cancel calls |

| SmartReadClient | AnthropicClient | scripted brief, error, empty output |
| SecretsStore | KeychainAccess | in-memory dictionary |
| NetworkReachability | NWPathMonitor | scripted reachable flag |

### Provider selection

Per read: preset provider if the frontmost bundle id has a preset, else the global default preset. If the chosen provider is ElevenLabs and no key is stored, or NetworkReachability reports unreachable, use Apple automatically and show "Using Apple voice: no ElevenLabs key" or ": offline" in the status line. Adding a key in Settings takes effect on the next read. A preset can pin Apple to keep an app fully local.

ElevenLabs request failures before the first audio chunk: a 401 (invalid key or quota exhausted, which ElevenLabs reports as 401 with a quota detail) stops the read, sets the error state and offers "Open Settings > Keys". Any other failure (connection error, DNS, captive portal, 429, 5xx, or no first chunk within 5 s) falls to Apple automatically with "Using Apple voice: ElevenLabs unavailable (<reason>)". Failures after the first chunk follow Mid-stream failure and resume.

### Per-app preset schema

```
AppPreset { bundleId: String?          nil = global default
            provider: elevenlabs | apple
            elevenLabsVoiceId: String
            appleVoiceByLanguage: [String: String]   BCP-47 language -> AVSpeechSynthesisVoice identifier
            speed: Double               0.7 ... 2.0, a playback multiplier (mapping in Speed)
            smartReadEnabled: Bool
            smartReadMode: brief | cleanup
            languageOverride: String?   BCP-47, nil = detect }
```
Resolution: exact bundle id match, else the global default. The default preset is created on first run with provider = elevenlabs unconditionally (Provider selection handles the no-key case), speed 1.0, smart read on, mode brief, and the system default Apple voice for the system language.

Menu-initiated reads (Speak clipboard, Smart read clipboard) use the global default preset, run the same size guard, and confirm an over-cap read through a "Read anyway" menu item instead of a second hotkey press.

### Speed

speed is one multiplier in the UI. ElevenLabs voice_settings.speed accepts 0.7 to 1.2 on Flash v2.5, so SpeedMapper sends min(speed, 1.2) to ElevenLabs and applies the remainder (speed / 1.2 when speed > 1.2) as the rate of an AVAudioUnitTimePitch node in the player chain, which preserves pitch. For Apple, SpeedMapper maps the multiplier onto AVSpeechUtterance.rate: AVSpeechUtteranceDefaultSpeechRate times speed, clamped to the minimum and maximum rate constants.

### Capture

1. AXIsProcessTrusted false: no capture. Icon switches to the warning state and the menu's first item becomes "Grant Accessibility access", which opens System Settings > Privacy & Security > Accessibility via the x-apple.systempreferences URL. Checked on every hotkey press, since a rebuild with a new signature silently drops the grant.
2. AXSelectedText on the focused element. Non-empty: done.
3. Fallback: snapshot the pasteboard, reading only materialised data for standard UTIs (public.utf8-plain-text, public.rtf, public.html, public.png, public.file-url) and skipping promised or lazily provided types; record changeCount N. Press the frontmost app's Edit > Copy menu item through Accessibility. Wait up to 300 ms for changeCount == N+1. Read the string. Restore the snapshot only if changeCount is still N+1 at restore time, writing the restore with org.nspasteboard.TransientType so clipboard managers ignore it. If the snapshot was incomplete (promised types skipped), the copy still proceeds and the restore is best-effort with the status line "Clipboard restored partially". The copy itself is performed by the source app and will appear in clipboard managers (Raycast, Maccy, Paste); this is accepted and stated in the README. Timeout or changeCount drift: no speech, never read stale clipboard contents, status line "Nothing selected".
4. Empty result: icon shakes briefly, no speech.

### Size guard

Hard cap, default 10,000 characters, configurable in Settings > General. Above the cap nothing is sent. The session enters awaitingConfirm, keeps the captured text, and the status line reads "Selection too long (23,400 characters). Press the shortcut again within 5 s to read anyway". The same hotkey within 5 s proceeds with the already captured text; the other hotkey or expiry returns to idle. The size guard is the only input limit; there is no separate smart-read budget.

### Chunking

Below the ElevenLabs input limit the whole text is one request. Above it, TextChunker splits at sentence boundaries, records each chunk's start offset in the spoken text, and passes previous_text and next_text for continuity. Chunk k+1 is requested as soon as chunk k has been fully received, so its first audio is buffered before chunk k finishes playing; buffers are appended to the same player node. Cancel tears down the in-flight request, the queued request and the player under the same SessionID.

### Language

LanguageDetector (NLLanguageRecognizer) runs on the captured text. ElevenLabs Flash v2.5 detects language itself. For Apple the precedence is languageOverride, then the detected language, then the system language; the voice is appleVoiceByLanguage[language] if set, else the best system voice for that language. Smart read prompts instruct Claude to answer in the source language unless the preset overrides it.

### Read flow

hotkey -> ReadSession.start -> capture -> size guard -> resolve preset -> provider.speak(text, preset). ElevenLabs: POST to the stream/with-timestamps endpoint with output_format pcm_24000. The response is newline-delimited JSON; each line carries base64 audio plus alignment and normalized_alignment. ElevenLabsProvider parses lines as they arrive, base64-decodes the audio into AVAudioPCMBuffer (Int16, 24 kHz, mono) scheduled on AVAudioPlayerNode, and reads character offsets from alignment (original characters, not normalized_alignment). Apple: AppleSpeechProvider speaks directly through AVSpeechSynthesizer behind the same SpeechProvider protocol and cancels with stopSpeaking(at: .immediate); it does not go through PCMStreamPlayer. Cancel on ElevenLabs tears down the URLSession task and the player node. Every callback carries the SessionID and is dropped if it does not match the current session.

### Hotkey x state

| State | Read hotkey | Smart read hotkey |
|---|---|---|
| idle (also error or warning display) | start read, clear Last error | start smart read, clear Last error |
| awaitingConfirm (read) | proceed with captured text | cancel |
| awaitingConfirm (smart read) | cancel | proceed with captured text |
| capturing | cancel | cancel |
| transforming | cancel | cancel |
| buffering | cancel | cancel |
| speaking | cancel | cancel |

Any press in a working state cancels and returns to idle; it never starts a new session, even with a new selection. Error and warning are display states over an idle session: the next hotkey press starts a new read and clears the error. Last error persists in the menu until the next successful read. "Read original instead" replays the text stored from the failed smart read, not a fresh capture.

### Smart read flow

Preconditions, checked after capture: preset has smartReadEnabled = false -> plain read of the selection with the status line "Smart read disabled for <app>"; no Anthropic key -> error state with "Open Settings > Keys"; unreachable network -> error state "Smart read needs a connection" with "Read original instead". Then the transforming step: await the full Claude response (Anthropic Messages API, model from Settings, default claude-haiku-4-5 for latency), then one TTS stream of the brief. Transform timeout 20 s. Budget for the 6 s criterion on a 5k-character input: Haiku response at or under 4 s, TTS first audio at or under 1 s, overhead under 1 s. Failures: API error, 429, 529, timeout, empty or refused output -> error state "Smart read failed: <reason>" with "Read original instead" as a one-click menu action. The hotkey cancels the pending request.

### Mid-stream failure and resume

If the ElevenLabs stream drops after the first chunk, the player stops at the last scheduled buffer. ReadSession knows the last played character offset in the spoken text (brief or selection) from the alignment data plus the chunk start offset recorded by TextChunker. It automatically continues with Apple from the start of the sentence containing that offset, without a click, and the status line reads "Continued with Apple voice: connection lost". A preset pinned to Apple never hits this path.

### Menu bar status

Icon states: idle, speaking, transforming (pulsing), warning (no Accessibility), error. Menu items: status line, Last error with its action, Stop, Speak clipboard, Smart read clipboard, Read anyway (only while awaitingConfirm from a menu read), Settings, Quit.

## Reviewer Concerns

Disposition: CONCERNS_RECORDED

Stop: MAX_ITERATIONS

### R3-1 — completeness

**Problem**

> Chunking prefetches chunk k+1 while chunk k is still playing, but the pre-first-chunk failure rule in Provider selection (401 -> error, anything else or no first chunk within 5 s -> Apple with 'ElevenLabs unavailable') is written for the first request of a read. For a prefetched request that fails or times out while chunk k is still audible, the document does not say whether the session switches to Apple immediately (cutting chunk k), waits until chunk k ends and continues with Apple from chunk k+1's recorded start offset, or retries, nor whether the 5 s no-first-chunk timer even applies when nothing is waiting on the audio yet.

**Remedy**

> State that a failed or timed-out prefetch request lets the already buffered audio finish, then continues with Apple from the failed chunk's start offset with the 'Continued with Apple voice' status line (401 still stops with the Keys action), and add 'prefetched chunk request fails' to the chunking tests.

### R3-2 — completeness

**Problem**

> Mid-stream failure says the player 'stops at the last scheduled buffer' and Apple resumes from the sentence containing the last played offset. With prefetch, chunk k+1's buffers may already be appended to the same player node when chunk k's stream drops, so the player would play chunk k's received portion and then jump straight into chunk k+1, skipping the lost tail of chunk k; the resume rule and the queued buffers conflict and no rule says whether the buffered chunk k+1 is discarded or kept.

**Remedy**

> Decide and document: on a drop in chunk k, discard any buffered chunk k+1 audio and continue with Apple from the last played sentence to the end of the spoken text (simplest, one resume path), or fill only the gap with Apple and then let chunk k+1 play; add the case to the 'mid-stream resume across chunk boundaries' test.

### R3-3 — completeness

**Problem**

> The size guard's only feedback is the menu status line 'Selection too long ... Press the shortcut again within 5 s to read anyway', but a hotkey-initiated read happens with the menu closed and the icon state list (idle, speaking, transforming, warning, error) has no awaitingConfirm state. The user who presses the hotkey on a long selection sees nothing change and has no cue that a second press is expected within 5 s; the confirmation window will almost always expire unnoticed.

**Remedy**

> Add an awaitingConfirm icon state (or a distinct shake/badge) so the pending confirmation is visible without opening the menu, and list it under Menu bar status.

### R3-4 — clarity

**Problem**

> Menu-initiated reads 'run the same size guard' and confirm through 'Read anyway', but the awaitingConfirm status line text is fixed to 'Press the shortcut again within 5 s', the Hotkey x state table has no row for a menu read in awaitingConfirm (does the read hotkey confirm it, cancel it, or start a fresh capture?), and it is not stated whether the 5 s expiry applies to a menu read, where the user must reopen the menu to click 'Read anyway'.

**Remedy**

> Add a 'awaitingConfirm (menu)' row to the table (hotkeys cancel; only 'Read anyway' proceeds), give the menu read its own status line wording ('... Click Read anyway within N s'), and state the expiry for menu reads (same 5 s, or longer since the menu must be reopened).

### R3-5 — clarity

**Problem**

> AppPreset.languageOverride is described generically as 'BCP-47, nil = detect', but the Language section applies it only to the Apple voice precedence and the smart read prompt, while 'ElevenLabs Flash v2.5 detects language itself'. Whether an override is sent to ElevenLabs as language_code (Flash v2.5 supports it) or ignored for ElevenLabs is not stated, so a preset with languageOverride = de-DE and provider = elevenlabs has unspecified behavior.

**Remedy**

> State either that languageOverride is passed as language_code on the ElevenLabs request, or that it only affects Apple and smart read and is ignored by ElevenLabs, and add that note to the schema comment.

### R3-6 — clarity

**Problem**

> Smart read failures (API error, 429, 529, timeout, empty output, unreachable network) all offer 'Read original instead', but the 'no Anthropic key' precondition offers only 'Open Settings > Keys', and 'Last error with its action' implies exactly one action per error. A user without an Anthropic key who presses the smart read hotkey therefore cannot hear the selection without re-selecting and pressing the other hotkey, and the single-action menu model does not say whether both actions can be shown.

**Remedy**

> State whether the no-key error also offers 'Read original instead' (and that Last error can carry two actions), or document why the no-key case intentionally has only the Keys action.

### R3-7 — consistency

**Problem**

> Capture step 1 says the menu's first item becomes 'Grant Accessibility access' in the warning state, but the Menu bar status item list (status line, Last error, Stop, Speak clipboard, Smart read clipboard, Read anyway, Settings, Quit) and the MenuBarView.swift line in the layout both omit it.

**Remedy**

> Add 'Grant Accessibility access (only in the warning state)' to the Menu bar status item list and the MenuBarView.swift layout line.

### R3-8 — consistency

**Problem**

> Capture gives two different outcomes for 'no text to read': the Copy-fallback timeout or changeCount drift sets the status line 'Nothing selected' with no shake, while step 4 'Empty result: icon shakes briefly, no speech' sets no status line. Both are the same user situation (hotkey pressed, nothing readable), and the timeout path's status line is only visible with the menu open, so a hotkey user gets no feedback for a timeout but a shake for an empty AX result.

**Remedy**

> Unify: every no-text outcome shakes the icon and sets the 'Nothing selected' status line, or state explicitly why the two cases differ.
